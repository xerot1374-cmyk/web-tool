# Internal doc update triggers

Update or create internal docs when a change affects:
- how engineers understand the system
- how contributors make changes safely
- how the system is operated, debugged, or recovered
- why a technical decision was made
- how agents should behave in this repo

Usually update docs for:
- feature or workflow additions
- architecture changes
- environment or deployment changes
- new modules, integrations, or dependencies
- repo policy or agent workflow changes

Usually skip doc updates for:
- typo fixes
- formatting-only edits
- behavior-neutral refactors
- isolated test edits that do not change understanding or operation
